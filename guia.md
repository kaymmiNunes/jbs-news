## Apresentação do projeto ao grupo

Grupo, a proposta de vocês é criar um **site informativo** chamado **JBS NEWS**, voltado para a divulgação de **eventos, reuniões, datas importantes e notícias de interesse da escola ou da comunidade ligada ao projeto**. Além disso, o site precisa ter preocupação com **acessibilidade para pessoas com deficiência** e também pode oferecer uma forma de o público **enviar sugestões de notícias para o e-mail do organizador do site**.

O mais importante durante o desenvolvimento é não tentar construir um portal muito complexo logo no início. O ideal é criar um projeto **simples, claro, funcional, acessível e organizado**, que possa ser concluído até agosto.

Vocês não precisam fazer um sistema avançado de jornal online. O melhor caminho é construir um site com páginas organizadas, seções de notícias, avisos importantes, boa leitura, navegação simples e alguns recursos básicos de acessibilidade. Se isso estiver funcionando bem, o projeto já terá muito valor.

Durante a produção, o grupo deve trabalhar com organização, divisão de tarefas, revisão constante, testes e registro das versões no GitHub. Isso ajuda a manter o projeto seguro, evita perda de arquivos e mostra a evolução do trabalho.

## 1. Análise simples da proposta do projeto

O projeto de vocês pretende criar um **site de comunicação e informação**, reunindo conteúdos importantes em um único lugar. A ideia é facilitar o acesso a notícias, datas, reuniões e avisos, deixando a informação mais acessível para todos.

### O que esse projeto pretende resolver

Muitas vezes, informações importantes ficam espalhadas em murais, grupos de mensagens ou avisos informais, e parte do público pode não receber tudo com clareza. Além disso, muitos sites esquecem da acessibilidade, dificultando o acesso para pessoas com deficiência.

O JBS NEWS pode ajudar a resolver isso ao reunir informações em um ambiente mais organizado, claro e fácil de navegar.

### Problema principal

O problema principal é a **dificuldade de centralizar e divulgar informações importantes de forma clara, acessível e organizada**.

### Objetivo geral da aplicação

O objetivo do site é **informar o público sobre eventos, reuniões, datas importantes e notícias, oferecendo também acessibilidade e uma forma simples de enviar sugestões de pauta ou notícia**.

### Utilidade do sistema no dia a dia

Esse site pode ser útil para:

- divulgar avisos importantes;
- mostrar calendário de eventos e reuniões;
- informar prazos, datas e comunicados;
- melhorar a organização da comunicação;
- permitir que pessoas acompanhem novidades com mais facilidade;
- tornar a informação mais acessível para diferentes usuários.

### Público-alvo

O público-alvo pode incluir:

- estudantes;
- professores;
- coordenação;
- funcionários;
- comunidade escolar;
- usuários que precisam de recursos de acessibilidade.

### Possíveis funções principais do sistema

O site pode incluir:

- página inicial com destaques;
- seção de notícias;
- seção de eventos e reuniões;
- área de datas importantes;
- página “sobre” explicando o objetivo do projeto;
- formulário ou botão para enviar sugestão de notícia;
- recursos básicos de acessibilidade;
- organização por cards ou blocos de aviso;
- filtro por categoria de informação;
- destaque para comunicados urgentes.

## 3. Levantamento de requisitos

### O que são requisitos

Requisitos são as necessidades do projeto. Eles mostram o que o sistema precisa fazer e como ele deve funcionar.

### Diferença entre requisitos funcionais e não funcionais

**Requisitos funcionais** são as funções do sistema.  
Exemplo: mostrar notícias, exibir eventos, permitir enviar sugestão.

**Requisitos não funcionais** são características de qualidade do sistema.  
Exemplo: ser acessível, fácil de usar, organizado e legível.

### Quais requisitos esse projeto provavelmente terá

Como o projeto é um site informativo com foco em comunicação, ele precisa exibir conteúdos importantes de forma clara, atualizada e acessível. Também precisa permitir navegação simples e apresentar boa leitura para diferentes públicos.

### Requisitos funcionais

- O sistema deve exibir uma página inicial.
- O sistema deve apresentar notícias e avisos.
- O sistema deve mostrar eventos, reuniões e datas importantes.
- O sistema deve possuir menu de navegação.
- O sistema deve destacar informações importantes na tela inicial.
- O sistema pode permitir filtrar ou separar informações por categoria.
- O sistema deve possuir uma forma de contato ou sugestão de notícia.
- O sistema pode abrir o e-mail do organizador pelo botão “enviar sugestão”.
- O sistema deve possuir páginas ou seções específicas para notícias e eventos.
- O sistema deve apresentar conteúdo de forma legível.

### Requisitos não funcionais

- O site deve ter linguagem clara e objetiva.
- O site deve ser organizado visualmente.
- O site deve funcionar em navegador comum.
- O site deve possuir recursos básicos de acessibilidade.
- O contraste entre texto e fundo deve facilitar a leitura.
- O site deve usar títulos claros e boa separação de conteúdo.
- Os arquivos devem estar organizados.
- O sistema deve ser simples de manter e atualizar.
- O projeto deve ser possível de concluir até agosto.

## 4. Tecnologias indicadas

Para esse projeto, a melhor escolha é usar tecnologias simples, adequadas para iniciantes e suficientes para criar um bom site informativo.

### HTML

HTML serve para criar a estrutura da página: títulos, textos, imagens, links, menus, seções e formulários.

### CSS

CSS serve para cuidar da aparência: cores, espaçamentos, fontes, contraste, tamanho do texto e organização visual.

### JavaScript

JavaScript pode ser usado para colocar interações simples, como:

- abrir e fechar menu em telas menores;
- destacar notícias;
- mostrar avisos;
- filtrar categorias;
- validar formulário;
- alternar tamanho de fonte ou modo de contraste.

### GitHub

GitHub serve para guardar o projeto, registrar a evolução do grupo e facilitar a organização dos arquivos.

### Tecnologias recomendadas para este projeto

- HTML
- CSS
- JavaScript
- Git e GitHub
- Editor de código, como VS Code

### Alternativa simples para ambiente escolar

A melhor opção para o grupo é criar um **site estático**, sem banco de dados e sem painel administrativo. As notícias e eventos podem ser cadastrados manualmente nos arquivos HTML no começo. Isso já atende bem ao projeto escolar.

Para o envio de sugestões por e-mail, uma alternativa simples é usar:

- um botão com link `mailto:` para abrir o e-mail do organizador; ou
- um formulário visual, mesmo que inicialmente sem envio real.

### Por que essas tecnologias são boas para esse projeto

Porque são:

- acessíveis para iniciantes;
- suficientes para um portal simples de notícias;
- fáceis de testar;
- adequadas ao prazo até agosto;
- boas para trabalhar acessibilidade básica no front-end.

## 7. Primeira versão do projeto

A primeira versão funcional não precisa estar perfeita. Ela precisa mostrar que a ideia já virou um site real e navegável.

### O que deve existir na primeira versão funcional

- página inicial pronta;
- menu funcionando;
- pelo menos 3 áreas de conteúdo, como notícias, eventos e datas importantes;
- visual básico organizado;
- pelo menos uma interação simples;
- pelo menos um recurso inicial de acessibilidade, mesmo que básico.

### O que pode estar simples ou incompleto

- número pequeno de notícias;
- layout ainda básico;
- poucas imagens;
- filtro ainda simples;
- formulário sem envio real;
- acessibilidade ainda em nível inicial.

### O que é mais importante nessa primeira entrega

O mais importante é que:

- o site abra corretamente;
- os links funcionem;
- as informações principais estejam visíveis;
- a proposta do portal informativo esteja clara;
- o site já demonstre preocupação com acessibilidade.

### Como saber se essa versão já pode ser apresentada

Ela já pode ser apresentada quando:

- o site funciona sem erro grave;
- as páginas principais abrem;
- existe conteúdo suficiente para demonstrar a proposta;
- o grupo consegue explicar o que já foi desenvolvido.

## 8. Orientação de commit no GitHub

### O que é commit

Commit é um registro de uma mudança feita no projeto. É como salvar uma etapa com uma mensagem explicando o que foi alterado.

### Por que usar GitHub

O GitHub ajuda a:

- guardar o projeto online;
- evitar perda de arquivos;
- registrar a evolução do grupo;
- organizar o trabalho;
- facilitar revisões.

### Como criar um repositório

1. Entrar no GitHub.
2. Clicar em **New repository**.
3. Escolher um nome, por exemplo: `jbs-news`.
4. Criar o repositório.
5. Copiar o link do repositório.

### Como organizar os arquivos antes de enviar

Antes de enviar:

- revisar os nomes dos arquivos;
- organizar as pastas;
- remover arquivos desnecessários;
- confirmar que o site abre normalmente.

### Exemplo de comandos básicos

```bash
git init
git add .
git commit -m "Estrutura inicial do projeto JBS NEWS"
git branch -M main
git remote add origin LINK_DO_REPOSITORIO
git push -u origin main
```

### Comandos para novas atualizações

```bash
git add .
git commit -m "Adiciona páginas de notícias e eventos"
git push
```

### Exemplos de mensagens de commit
